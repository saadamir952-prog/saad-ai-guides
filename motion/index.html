The method in 30 seconds

1
Describe the video. Subject, style, length, camera, what happens when. The prompt is the brief — the more specific it is, the better the code.
2
Claude writes the code. A Three.js scene, a Remotion project, or a Blender Python script. Text in, program out. No frames are generated.
3
You render it. Open the HTML file in a browser, run the Remotion project, or run the Blender script. The MP4 comes out of your render, not out of the model.
4
Watch it, fix it, re-render. Tell Claude what looks wrong, it patches the code, you render again. That loop is the workflow — budget for several rounds.

Why code, not frames?

  • Everything is editable. The type, the colours, the timing, the camera — all of it is code you can open, change and re-render. A video model gives you pixels you can only watch.
  • Nothing is hallucinated twice. A video model redraws every frame; code renders the same scene deterministically, every time.
  • It can look at its own work. Render the frames, show them back to Claude, and it fixes the code. The render–review–fix loop actually works because the model can see what it made.

The two code routes

Three.js — one HTML file. Best for 3D scenes, product spins, animated diagrams and data visualisation. The whole video is a single HTML file: open it in any browser and it plays. Record the browser window, or export the frames and encode them to MP4.

Remotion — video in React. Best for kinetic typography, captions, templates and programmatic edits. You describe compositions in React code, and Remotion renders them to MP4 from the command line. If your video is mostly type and layout, this is the faster route.

A third route exists — Blender Python scripts for full 3D films — but start with Three.js or Remotion. They render in minutes, not hours.

What the code looks like

A minimal Three.js scene — the kind of code Claude writes for a 3D shot. This is an illustration of the shape of the code, not the scene from the video:

// A minimal Three.js scene: one object, one light, one camera move.
import * as THREE from 'three';
const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(45, 9/16, 0.1, 100);
camera.position.z = 6;
const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(1080, 1920);
document.body.appendChild(renderer.domElement);
const mesh = new THREE.Mesh(
  new THREE.TorusKnotGeometry(1, 0.35, 128, 32),
  new THREE.MeshStandardMaterial({ color: 0xff4d00 })
);
scene.add(mesh);
scene.add(new THREE.AmbientLight(0xffffff, 0.8));
function animate() {
  requestAnimationFrame(animate);
  mesh.rotation.x += 0.005;
  mesh.rotation.y += 0.01;
  renderer.render(scene, camera);
}
animate();

That is the whole idea: a scene, a camera, an object, a loop. Claude writes this from your description — you describe the object, the light and the camera move, and it writes the program that draws them.

Render it to MP4

Three.js single file: open it in Chrome and record the window (OBS, QuickTime, or any screen recorder). Or export the frames and encode them:

ffmpeg -framerate 60 -i frame_%04d.png -c:v libx264 -pix_fmt yuv420p out.mp4

Remotion: render a composition straight to MP4 from the command line:

npx remotion render <CompositionId> out.mp4

Either way, the MP4 is produced on your machine. If the code has a bug, you see a broken frame — paste the error back to Claude and it fixes the code.

Honest limits

  • It writes code, it doesn’t film. No camera, no real footage, no photoreal people. Motion graphics, 3D scenes, charts and kinetic type — that is the lane. For photoreal humans and lifestyle footage, a video model is still the right tool.
  • You need Claude Code. The code-writing happens inside Claude Code, which needs a paid Claude plan. This is not a free web tool you open in a tab.
  • The first render is rarely the keeper. Budget for several render–review–fix rounds. Vague briefs get vague films — name the style, the length and the camera.
  • Code output burns tokens. Fable 5.2, the Anthropic model built for this kind of work, costs $8 per million input tokens and $40 per million output tokens on the API; short films in independent tests cost $1.40–$4.25 in tokens. Set a budget before you start iterating.
  • You still have to render. Claude hands you code; the MP4 comes from your browser, Remotion or Blender. If the code has a bug, you see a broken frame — paste the error back and it fixes it.
  • No real footage generation. Photos, screen recordings and footage are yours to supply. Code can draw a scene; it cannot film your desk.
