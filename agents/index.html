The 2 install commands (copy-paste)

Path A — inside Claude Code (no terminal needed). Open Claude Code and run these two commands, one after the other:

/plugin marketplace add https://github.com/affaan-m/ECC
/plugin install ecc@ecc

That installs the whole plugin: all 72 agents, 328 skills, and 99 commands. Verify it worked:

/plugin list

You should see ecc@ecc enabled.

Path B — the guided setup (the README’s recommended path). If you prefer a wizard that handles updates, scope, and hook settings, run this in your terminal instead. Prerequisites: Node.js 18 or newer, Git, and Claude Code 2.1 or newer.

npx ecc-universal@2.2.3 setup

For a typical personal setup, choose Global user, choose Standard hooks, and confirm. Then start a new Claude Code session and run /plugin list to verify ecc@ecc is enabled.

Pick ONE path. Both install the same ecc@ecc plugin. Do not stack them — installing ECC twice into the same setup can duplicate skills, commands, and hooks.

Which agents to switch on first

The README’s own advice: start with the workflow you need, not the full catalog. Seventy-two agents is a team, not a to-do list. These six cover the work most people do first:

1
planner — plan the feature first. /ecc:plan "describe the feature" — planner writes the implementation blueprint before any code exists. Always first.
2
tdd-guide — write code tests-first. The tdd-workflow skill — write the failing test, then the code that passes it. Same skill for fixing bugs: reproduce it with a failing test first.
3
code-reviewer — review what you just wrote. /code-review — a fresh-context review of new code, before it ships.
4
build-error-resolver — fix the failing build. /build-fix — one agent whose only job is build errors.
5
security-reviewer — check for holes. /security-scan — reads every line for vulnerabilities before production.
6
e2e-runner — test the real user flow. The e2e-testing skill — end-to-end tests on the critical path, not just unit tests.

Two more worth knowing on day one: architect (design the system architecture, alongside /ecc:plan) and go-reviewer (/go-review, if you write Go). The other 64 agents are specialists by language and domain — call them when the work calls for them.

It learns the way you code

One command reads your git history and writes the way you code into skills the agents reuse:

/skill-create

Run it after the install, once you have some history in the repo. It turns your own patterns — how you structure code, how you test, how you name things — into skills ECC applies next time. That is the part most people skip, and the part that makes the agents feel like yours instead of generic.

The official repo

Install only from the official project:

github.com/affaan-m/ECC

The official channels are the GitHub repo, the npm packages ecc-universal and ecc-agentshield, the GitHub App, the plugin slug ecc@ecc, and ecc.tools. The project’s own warning, from its README: third-party re-uploads and unofficial mirrors are not maintained or reviewed by the project and may contain malware. If the install source is not one of the official channels above, do not run it.

The catch

Seventy-two agents is a lot — and that is the trap. If you try to use all of them on day one, you will spend the day configuring instead of building. Start with the six above, one workflow at a time. The agents are only as good as the plan: skip the planner and the rest of the team builds the wrong thing faster. And remember the install rule: one path, once — never stack two installs into the same setup.
